## Wallet connection: chose Privy over Dynamic

Decision: use **Privy** (`@privy-io/react-auth`) for wallet connection + onboarding.

Rationale (from user):
- More customizable than Dynamic.
- Must not show red or any off-brand colors in the login modal — has to match Unora's scheme.
- Embedded wallets let non-crypto-native users onboard without a seed phrase (hackathon judging angle).
- Privy is also a $5,000 sponsor bounty.

### Verified facts (checked against official docs, not assumed)

- Privy docs explicitly name Monad as supported: "compatible with any EVM-compatible chain... Ethereum Mainnet, Base, Polygon, Arbitrum, Monad, Berachain, MegaETH, Mantle, Story."
- Monad is **not** in Privy's default chain list, so it must be configured explicitly via `defaultChain` + `supportedChains`.
- `viem/chains` exports both `monadTestnet` (id `10143`, name "Monad Testnet", symbol MON, rpc `https://testnet-rpc.monad.xyz`, testnet: true) and `monad` (id `143`, mainnet). Confirmed by reading the viem chain definition sources.
- Monad Testnet per Monad docs: chain ID `10143` (`0x279f`), currency `MON`, explorer `https://testnet.monadvision.com`, faucet `https://faucet.monad.xyz`. Note: testnet was reset from genesis on 2025-12-16.
- Privy `appearance` config fields available: `theme` ('light' | 'dark' | custom object), `accentColor`, `logo`, `landingHeader`, `loginMessage`, `showWalletLoginFirst`, `walletChainType`, `walletList`.
- `appearance.walletList` must be set explicitly, otherwise the modal renders a long alphabetical list of every supported wallet (1inch, AB Pay, ...). Scope it to `['detected_wallets']`.
- `defaultChain` must also appear in `supportedChains` or `PrivyProvider` throws. Empty `supportedChains` also throws.
- Rainbow Wallet mobile does not support testnets and rejects connection if a testnet is `defaultChain` — relevant since Unora targets Monad testnet.

### Notable design decision

`LoanRequestStep` computes **two independent caps** and reports which one binds:
`min(loanCeiling, collateralBalance / collateralRatio)`. For the mock numbers the collateral balance
binds ($12,142) rather than the ceiling ($12,400), and the UI names the binding constraint. That's the
mechanic worth showing — the ceiling comes from the score, the collateral cap from the wallet.

- **`src/pages/BorrowPage.tsx`** (rewritten) — public market list. Header = title + Total deposits /
  Total loans + `ConnectWalletButton`. Then a state strip: disconnected → soft `ConnectBanner`

  ratio, ceiling, term). Then pool filter chips, a real asset search, and a sort select
  (Liquidity / Lowest APR / Total borrows). Then one section per pool with a per-pool total borrowed.
  The wizard only replaces the list when a market is picked **and** a wallet is present.

### Market-aware rates

Picking WBTC (3.10%) must not show USDC's 4.20%. So the protocol math now takes an optional rate:

```ts
export function interestFor(amount: number, apr: number = PROTOCOL.apr): number
export function totalRepayable(amount: number, apr: number = PROTOCOL.apr): number
export function streamRatePerSecond(amount: number, apr: number = PROTOCOL.apr): number
```

Backward compatible — `PROTOCOL.apr` is still the default. `LoanRequestStep`, `CollateralLockStep`
and `LoanActiveStep` each gained an optional `market?: Market` prop that supplies both the rate and
the denomination symbol. Collateral stays USDC (you lock USDC, borrow the market asset) — that is
deliberate, not an oversight.

Verified over CDP: USDC gives $51.78 interest / 0.000650 USDC per sec; WBTC gives $38.22 /
$5,038.22 total on the same $5,000 — matches `5000 × 0.031 × 90/365`.

### Gotchas worth keeping

- **`flex-1` overrides a fixed height.** `<div className="flex flex-col flex-1 h-[454px]">` does not
  produce a 454px box — `flex: 1 1 0%` sets flex-basis 0 and lets content win, so each tab sized to
  its own content and the card jumped 26px on every toggle. Drop `flex-1` when you want a pinned
  height. Verified over CDP by clicking each tab and reading the card's height.
- **Full-width SVG charts need a wide viewBox.** A `420x300` viewBox stretched to a 1000px card
  renders ~740px tall *and* shrinks the axis labels to unreadable. `1000x340` keeps the plot ~340px
  and the labels at their true 11px.
- **`netApy` is `number | null`.** A rate on a zero-or-negative net position is undefined; returning
  0 rendered a fabricated "+0.00%" for a borrower with no deposits. The card shows "—" instead.
- **Net APY and Net interest are different kinds of number** — the former is forward-looking and
  annualised on net position, the latter cumulative to date. Both correct, but the hints have to say
  so or a judge will (fairly) ask.

### Restarting the dev server after a `bun add`

`bun add` changes the lockfile, so Vite re-optimises deps and tries to delete
`node_modules/.vite/deps` — which trips the sandbox bulk-delete guard (the error is
`[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]`). **`mv node_modules/.vite /tmp/vite-cache-$(date
+%s)`** and restart. Do not try to `rm` it. This has now bitten twice; it is the first thing to check
when the dev server returns 502 after installing anything.

### ⚠️ The `TSC_EXIT` check in my scripts has been lying

`echo "TSC_EXIT=${PIPESTATUS[0]:-$?}"` **always prints 0** in this shell. `PIPESTATUS` is bash
syntax; **the shell here is zsh**, which uses lowercase `$pipestatus` (1-indexed). So the expansion
is empty, the `:-` fallback fires, and `$?` is the *last* command in the pipeline (`head`), which is
always 0.

Every "tsc exits 0" I reported this session was therefore unverified — and one run did in fact have
real errors (`Cannot find name 'tokenAccent'`) that the check reported as success.

**Use this instead:**

```sh
./node_modules/.bin/tsc -b --pretty false > /tmp/tsc.log 2>&1; echo "TSC_EXIT=$?"; cat /tmp/tsc.log
```

No pipe, so `$?` is genuinely tsc's. Also check the *output*, not just the code.
